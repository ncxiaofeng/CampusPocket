## 冻小梨 0.5.4 · 登录与一卡通修复

本版集中修复「统一认证明明显示已登录，课表/一卡通却一直提示过期」的问题，并顺带把校内登录入口改成更可靠的教务 SSO 网页授权。

### 统一认证 / 教务

- **CAS 主凭据整套保存**：`CASTGC` 之外同时保留 CAS 主域的 `route` 与 `JSESSIONID`。`route` 是 CAS 集群的粘性会话路由，之前只存 `CASTGC` 会导致换票请求落到没有该 TGT 的节点，表现就是“刚登录就过期”。从零信任代理域镜像 `CASTGC` 时只取 ticket，并与主域已有 Cookie 合并，不再清掉 `route`。
- **校内登录改走教务 SSO 页**：校内点「统一身份认证」直接打开 `172.20.130.13/sso/jziotlogin`，由 WebView 执行完整重定向，一次同时拿到统一认证 `CASTGC` 和教务 `JSESSIONID`，不再依赖 OkHttp 静默换票。登录成功落到课表页，返回 App 即可同步。
- **校外代理更严格**：只有真正映射到教务的 `172-20-130-13.atrust.ecut.edu.cn` 会话才算 WebVPN 代理就绪；门户主页 `atrust1.ecut.edu.cn` 的 Cookie 不再误判。代理失败会提示打开零信任门户，而不是把用户送回统一认证反复登录。
- **换票成功判定更严格**：只有最终响应 2xx 且已离开 CAS 域才算成功；正方 `jziotlogin` 校验 ticket 失败会返回 500，旧逻辑会误判成功。
- 教务请求支持直连/代理候选与自动回退，并优先复用最近一次成功的地址。

### 校园卡 / 一卡通

- 一卡通接口遇到 **401/403** 时不再直接抛错：
  1. 用 `CASTGC` 静默重建 ehall 会话；
  2. 预热官方卡片页上下文（卡片页 + `getAppConfig.do` + `emappagelog/config/psxykapp.do`）；
  3. 重试原请求一次。
- 仍失败时提示「打开官方页」，按钮直接进入校园卡官方页；加载一次后返回刷新即可。
- 去掉同源 XHR 不需要的 `Origin` 头，请求头与官方网页保持一致。

### 升级提示

- 安装后请**重新登录一次**（旧数据没有 `route`，必须刷新）：
  - 校内：更多 → 统一身份认证 → 登录，落到课表页后返回，点同步。
  - 校外：先登录统一认证，再在零信任门户打开一次「新教务管理系统」，返回后同步。
- 校园卡若提示会话/权限问题，点校园卡页右上角「官方页」加载一次，再返回刷新。

### 说明

- 仍然只读：不保存账号密码、不接后端、不提交任何教务/一卡通业务操作。
- 会话 Cookie 继续保存在本机 SQLCipher 加密库中。
